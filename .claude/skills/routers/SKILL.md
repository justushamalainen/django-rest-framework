# DRF Routers

Routers provide a convenient and consistent way of automatically generating URL patterns for your ViewSets. Instead of manually defining URL patterns for each action (list, create, retrieve, update, delete), routers do this automatically based on ViewSet methods.

## What You'll Learn

After mastering this skill, you will be able to:

- Choose between SimpleRouter and DefaultRouter for your use case
- Register ViewSets with routers using proper prefix and basename patterns
- Understand the URL patterns generated by routers (list, detail, and custom actions)
- Use @action decorator to create custom endpoints
- Create custom router classes with specialized URL patterns
- Handle nested routing patterns (e.g., /users/1/posts/)
- Configure trailing slashes and URL path types (regex vs simple)
- Debug routing issues and URL reversal problems
- Integrate router URLs into Django's URLconf
- Understand when NOT to use routers (and use regular views instead)

## Before You Start

**Prerequisites:**
- Django URL patterns and URLconf basics
- DRF ViewSets (ModelViewSet, ReadOnlyModelViewSet)
- Basic understanding of REST API URL design
- HTTP methods (GET, POST, PUT, PATCH, DELETE)

**Key Concepts:**
- Routers automatically generate URL patterns from ViewSets
- A ViewSet is a class that combines logic for multiple related views
- SimpleRouter provides basic CRUD URL patterns
- DefaultRouter extends SimpleRouter with an API root view
- The @action decorator creates custom endpoints beyond CRUD
- basename is used for URL name generation (e.g., 'user-list', 'user-detail')

## Quick Start

Here's a complete working example:

```python
# models.py
from django.db import models

class Author(models.Model):
    name = models.CharField(max_length=100)
    email = models.EmailField(unique=True)
    active = models.BooleanField(default=True)

    def __str__(self):
        return self.name

class Book(models.Model):
    title = models.CharField(max_length=200)
    author = models.ForeignKey(Author, on_delete=models.CASCADE, related_name='books')
    isbn = models.CharField(max_length=13, unique=True)
    published_date = models.DateField()

    def __str__(self):
        return self.title

# serializers.py
from rest_framework import serializers
from .models import Author, Book

class AuthorSerializer(serializers.ModelSerializer):
    class Meta:
        model = Author
        fields = ['id', 'name', 'email', 'active']

class BookSerializer(serializers.ModelSerializer):
    class Meta:
        model = Book
        fields = ['id', 'title', 'author', 'isbn', 'published_date']

# views.py
from rest_framework import viewsets, status
from rest_framework.decorators import action
from rest_framework.response import Response
from .models import Author, Book
from .serializers import AuthorSerializer, BookSerializer

class AuthorViewSet(viewsets.ModelViewSet):
    """
    A ViewSet for viewing and editing authors.
    Automatically provides `list`, `create`, `retrieve`, `update`, and `destroy` actions.
    """
    queryset = Author.objects.all()
    serializer_class = AuthorSerializer

    @action(detail=True, methods=['get'])
    def books(self, request, pk=None):
        """
        Custom action to get all books by this author.
        URL: /authors/{id}/books/
        """
        author = self.get_object()
        books = author.books.all()
        serializer = BookSerializer(books, many=True)
        return Response(serializer.data)

    @action(detail=True, methods=['post'])
    def activate(self, request, pk=None):
        """
        Custom action to activate an author.
        URL: /authors/{id}/activate/
        """
        author = self.get_object()
        author.active = True
        author.save()
        serializer = self.get_serializer(author)
        return Response(serializer.data)

    @action(detail=False, methods=['get'])
    def recent(self, request):
        """
        Custom list action to get recently added authors.
        URL: /authors/recent/
        """
        recent_authors = Author.objects.order_by('-id')[:10]
        serializer = self.get_serializer(recent_authors, many=True)
        return Response(serializer.data)

class BookViewSet(viewsets.ModelViewSet):
    """
    A ViewSet for viewing and editing books.
    """
    queryset = Book.objects.select_related('author').all()
    serializer_class = BookSerializer

# urls.py
from django.urls import path, include
from rest_framework.routers import DefaultRouter
from .views import AuthorViewSet, BookViewSet

# Create a router and register our ViewSets
router = DefaultRouter()
router.register(r'authors', AuthorViewSet, basename='author')
router.register(r'books', BookViewSet, basename='book')

# The API URLs are now determined automatically by the router
urlpatterns = [
    path('api/', include(router.urls)),
]

# This generates the following URLs:
# GET    /api/                      -> API root (DefaultRouter only)
# GET    /api/authors/              -> list all authors
# POST   /api/authors/              -> create new author
# GET    /api/authors/{id}/         -> retrieve specific author
# PUT    /api/authors/{id}/         -> update author (full)
# PATCH  /api/authors/{id}/         -> update author (partial)
# DELETE /api/authors/{id}/         -> delete author
# GET    /api/authors/{id}/books/   -> custom action: list author's books
# POST   /api/authors/{id}/activate/ -> custom action: activate author
# GET    /api/authors/recent/       -> custom action: recent authors
# (Same pattern for /api/books/)
```

**Testing the API:**

```bash
# List all authors
curl http://localhost:8000/api/authors/

# Create a new author
curl -X POST http://localhost:8000/api/authors/ \
  -H "Content-Type: application/json" \
  -d '{"name": "Jane Doe", "email": "jane@example.com"}'

# Get specific author
curl http://localhost:8000/api/authors/1/

# Update author (partial)
curl -X PATCH http://localhost:8000/api/authors/1/ \
  -H "Content-Type: application/json" \
  -d '{"active": false}'

# Custom action: Get author's books
curl http://localhost:8000/api/authors/1/books/

# Custom action: Activate author
curl -X POST http://localhost:8000/api/authors/1/activate/

# Custom action: Get recent authors
curl http://localhost:8000/api/authors/recent/
```

## Decision Tree: SimpleRouter vs DefaultRouter

Use this decision tree to choose the right router:

```
START: Do you need an API root view?
│
├─ YES → Use DefaultRouter
│   └─ DefaultRouter provides:
│       ├─ GET / -> Browsable API root with links to all endpoints
│       ├─ Format suffixes (.json, .api)
│       └─ All features of SimpleRouter
│       └─ Best for: Browsable APIs, documentation, discoverability
│
└─ NO → Question 2
    └─ Question 2: Do you need format suffixes (.json, .api)?
        ├─ YES → Use DefaultRouter (set include_root_view=False if needed)
        └─ NO → Use SimpleRouter
            └─ SimpleRouter provides:
                ├─ Clean, minimal URL patterns
                ├─ List and detail routes
                ├─ Support for @action decorator
                └─ Best for: APIs without browsable UI, microservices
```

**When to use each:**

**DefaultRouter (most common choice):**
- Development APIs with browsable interface
- Public APIs where discoverability is important
- When you want an API root view listing all endpoints
- When you want format suffixes (.json, .api)
- Example: 80% of DRF projects use this

**SimpleRouter:**
- Production APIs without browsable interface
- Microservices where minimal URLs are preferred
- When you don't need an API root view
- When you want clean URLs without format suffixes
- Example: Internal APIs, performance-critical services

**Custom Router:**
- When you need non-standard URL patterns
- When integrating with legacy URL structures
- When you need special route handling
- Example: See [reference/custom-routers.md](./reference/custom-routers.md)

**No Router (regular views):**
- Single endpoint or very few endpoints
- Non-standard operations that don't fit CRUD
- When you need full control over URL structure
- Example: Authentication endpoints, webhooks, RPC-style APIs

## Common Mistakes & How to Fix Them

### ❌ Mistake 1: Forgetting to include router URLs

**Wrong:**
```python
# urls.py
from rest_framework.routers import DefaultRouter
from .views import AuthorViewSet

router = DefaultRouter()
router.register(r'authors', AuthorViewSet)

urlpatterns = [
    # Nothing here! URLs are not included
]
```

**Why it fails:** Registering ViewSets doesn't automatically add URLs to your project.

**✅ Correct:**
```python
from django.urls import path, include
from rest_framework.routers import DefaultRouter
from .views import AuthorViewSet

router = DefaultRouter()
router.register(r'authors', AuthorViewSet)

# Option 1: Include with path prefix
urlpatterns = [
    path('api/', include(router.urls)),
]

# Option 2: Include directly
urlpatterns = router.urls

# Option 3: Extend existing patterns
urlpatterns = [
    path('custom/', some_view),
] + router.urls
```

**Test:** Visit /api/ - you should see your endpoints.

---

### ❌ Mistake 2: Not specifying basename when queryset is not defined

**Wrong:**
```python
class AuthorViewSet(viewsets.ViewSet):  # Not ModelViewSet!
    # No queryset attribute

    def list(self, request):
        authors = Author.objects.all()
        serializer = AuthorSerializer(authors, many=True)
        return Response(serializer.data)

# urls.py
router.register(r'authors', AuthorViewSet)  # WILL CRASH!
```

**Why it fails:** Router needs basename to generate URL names. Without a queryset, it can't auto-determine the basename.

**✅ Correct:**
```python
# Explicitly provide basename
router.register(r'authors', AuthorViewSet, basename='author')

# Now URL names work:
# - author-list
# - author-detail
# etc.
```

**Test:** Run `python manage.py show_urls` - you should see proper URL names.

---

### ❌ Mistake 3: Using @action on non-ViewSet classes

**Wrong:**
```python
from rest_framework.views import APIView
from rest_framework.decorators import action

class AuthorView(APIView):  # Not a ViewSet!
    @action(detail=True)  # Won't work!
    def activate(self, request, pk=None):
        pass
```

**Why it fails:** @action decorator only works with ViewSets, not APIView or function-based views.

**✅ Correct:**
```python
# Option 1: Use ViewSet
from rest_framework import viewsets

class AuthorViewSet(viewsets.ModelViewSet):
    queryset = Author.objects.all()
    serializer_class = AuthorSerializer

    @action(detail=True, methods=['post'])
    def activate(self, request, pk=None):
        # Works!
        pass

# Option 2: Use regular URL patterns for APIView
from rest_framework.views import APIView

class AuthorActivateView(APIView):
    def post(self, request, pk):
        # Handle activation
        pass

# urls.py
urlpatterns = [
    path('authors/<int:pk>/activate/', AuthorActivateView.as_view()),
]
```

**Test:** Router should generate the custom action URL automatically.

---

### ❌ Mistake 4: Incorrect @action detail parameter

**Wrong:**
```python
class AuthorViewSet(viewsets.ModelViewSet):
    queryset = Author.objects.all()
    serializer_class = AuthorSerializer

    @action(detail=False, methods=['get'])  # Wrong! Needs an ID
    def activate(self, request, pk=None):
        """Should activate a specific author"""
        author = self.get_object()  # This will fail!
        author.active = True
        author.save()
        return Response({'status': 'activated'})
```

**Why it fails:** `detail=False` creates a list-level action (/authors/activate/), but the code expects an object ID.

**✅ Correct:**
```python
# For detail actions (operate on specific object)
@action(detail=True, methods=['post'])  # /authors/{id}/activate/
def activate(self, request, pk=None):
    author = self.get_object()  # Works!
    author.active = True
    author.save()
    return Response({'status': 'activated'})

# For list actions (don't need specific object)
@action(detail=False, methods=['get'])  # /authors/recent/
def recent(self, request):
    authors = Author.objects.order_by('-created')[:10]
    serializer = self.get_serializer(authors, many=True)
    return Response(serializer.data)
```

**Test:** detail=True should require an ID in the URL; detail=False should not.

---

### ❌ Mistake 5: Duplicate basename registration

**Wrong:**
```python
router = DefaultRouter()
router.register(r'authors', AuthorViewSet, basename='author')
router.register(r'writers', AnotherAuthorViewSet, basename='author')  # CRASH!
```

**Why it fails:** Each basename must be unique within a router. URL name conflicts will occur.

**✅ Correct:**
```python
router = DefaultRouter()
router.register(r'authors', AuthorViewSet, basename='author')
router.register(r'writers', AnotherAuthorViewSet, basename='writer')  # Unique!

# Now you have:
# - author-list, author-detail
# - writer-list, writer-detail
```

**Test:** Django will raise `ImproperlyConfigured` on duplicate basename.

---

### ❌ Mistake 6: Registering the same ViewSet multiple times with different prefixes

**Wrong assumption:**
```python
router = DefaultRouter()
router.register(r'authors', AuthorViewSet)
router.register(r'api/v2/authors', AuthorViewSet)  # Different prefix, same ViewSet
```

**Why this might confuse:** Both registrations work, but they share the same basename. You need unique basenames for proper URL reversal.

**✅ Correct:**
```python
router = DefaultRouter()
router.register(r'authors', AuthorViewSet, basename='author-v1')
router.register(r'api/v2/authors', AuthorViewSet, basename='author-v2')

# Or use separate routers for versioning
router_v1 = DefaultRouter()
router_v1.register(r'authors', AuthorViewSet, basename='author')

router_v2 = DefaultRouter()
router_v2.register(r'authors', AuthorV2ViewSet, basename='author')

urlpatterns = [
    path('api/v1/', include(router_v1.urls)),
    path('api/v2/', include(router_v2.urls)),
]
```

**Test:** Use reverse() to generate URLs - they should point to the correct version.

---

### ❌ Mistake 7: Expecting router to work with non-ViewSet classes

**Wrong:**
```python
from rest_framework import generics

class AuthorList(generics.ListCreateAPIView):
    queryset = Author.objects.all()
    serializer_class = AuthorSerializer

# urls.py
router.register(r'authors', AuthorList)  # Won't work!
```

**Why it fails:** Routers only work with ViewSet classes, not generic views or APIView.

**✅ Correct:**
```python
# Option 1: Convert to ViewSet
from rest_framework import viewsets

class AuthorViewSet(viewsets.ModelViewSet):
    queryset = Author.objects.all()
    serializer_class = AuthorSerializer

router.register(r'authors', AuthorViewSet)

# Option 2: Use manual URL patterns for generics
from django.urls import path

urlpatterns = [
    path('authors/', AuthorList.as_view(), name='author-list'),
    path('authors/<int:pk>/', AuthorDetail.as_view(), name='author-detail'),
]
```

**Test:** Router registration should work without errors.

## URL Patterns Generated by Routers

Understanding what URLs routers create is crucial for debugging and API design.

### SimpleRouter URL Patterns

```python
from rest_framework.routers import SimpleRouter

router = SimpleRouter()
router.register(r'authors', AuthorViewSet, basename='author')
```

**Generated URLs:**

| URL Pattern | HTTP Method | Action | URL Name | Description |
|-------------|-------------|--------|----------|-------------|
| /authors/ | GET | list | author-list | List all authors |
| /authors/ | POST | create | author-list | Create new author |
| /authors/{pk}/ | GET | retrieve | author-detail | Get specific author |
| /authors/{pk}/ | PUT | update | author-detail | Update author (full) |
| /authors/{pk}/ | PATCH | partial_update | author-detail | Update author (partial) |
| /authors/{pk}/ | DELETE | destroy | author-detail | Delete author |

**Custom actions (@action decorator):**

```python
@action(detail=True, methods=['post'])
def activate(self, request, pk=None):
    pass

# Generates: POST /authors/{pk}/activate/ (author-activate)

@action(detail=False, methods=['get'])
def recent(self, request):
    pass

# Generates: GET /authors/recent/ (author-recent)
```

### DefaultRouter URL Patterns

DefaultRouter generates all SimpleRouter URLs plus:

| URL Pattern | HTTP Method | Action | URL Name | Description |
|-------------|-------------|--------|----------|-------------|
| / | GET | api_root | api-root | API root view with links |

The root view returns:

```json
{
    "authors": "http://localhost:8000/api/authors/",
    "books": "http://localhost:8000/api/books/"
}
```

### Configuration Options

```python
# Trailing slashes (default: True)
router = DefaultRouter(trailing_slash=False)
# URLs: /authors instead of /authors/

# Use simple path() instead of re_path() (Django 2.0+)
router = SimpleRouter(use_regex_path=False)

# Customize root view
router = DefaultRouter()
router.root_view_name = 'custom-api-root'

# Disable format suffixes
router = DefaultRouter()
router.include_format_suffixes = False
# No .json or .api suffix URLs

# Disable root view
router = DefaultRouter()
router.include_root_view = False
```

## Troubleshooting

### "basename argument not specified, and could not automatically determine the name"

**Cause:** ViewSet doesn't have a `queryset` attribute and basename wasn't provided.

**Solution:**
```python
# Option 1: Add queryset attribute
class AuthorViewSet(viewsets.ViewSet):
    queryset = Author.objects.all()  # Add this

# Option 2: Provide basename explicitly
router.register(r'authors', AuthorViewSet, basename='author')
```

### "Router with basename 'X' is already registered"

**Cause:** Trying to register two ViewSets with the same basename.

**Solution:**
```python
# Use unique basenames
router.register(r'authors', AuthorViewSet, basename='author')
router.register(r'writers', WriterViewSet, basename='writer')  # Different!
```

### Custom @action not appearing in URL patterns

**Cause:** Various possible issues.

**Solutions:**
```python
# 1. Make sure it's a ViewSet, not APIView
class MyViewSet(viewsets.ModelViewSet):  # Not APIView!

# 2. Check @action syntax
@action(detail=True, methods=['post'])  # Correct
def my_action(self, request, pk=None):
    pass

# 3. Verify ViewSet is registered
router.register(r'prefix', MyViewSet)

# 4. Check the ViewSet actually implements the action method
# 5. Run: python manage.py show_urls (if installed)
```

### "Reverse for 'author-detail' not found"

**Cause:** URL name doesn't match or router URLs not included.

**Solution:**
```python
# 1. Verify basename matches
router.register(r'authors', AuthorViewSet, basename='author')
# Creates: author-list, author-detail, etc.

# 2. Make sure router.urls is included
urlpatterns = [
    path('api/', include(router.urls)),
]

# 3. Use correct URL name
from django.urls import reverse
url = reverse('author-detail', kwargs={'pk': 1})
```

## Performance Tips

1. **Optimize ViewSet querysets** - Use select_related() and prefetch_related()
2. **Use ReadOnlyModelViewSet** when you don't need write operations
3. **Limit @action methods** - Each action adds URL resolution overhead
4. **Use pagination** - Always paginate list views
5. **Cache router.urls** - URLs are cached automatically after first access
6. **Profile URL resolution** - Use Django Debug Toolbar to identify slow URL patterns

## When NOT to Use Routers

Routers are not always the best choice. Use regular URL patterns when:

1. **Single endpoint** - One or two views don't benefit from router overhead
2. **Non-CRUD operations** - Authentication, webhooks, file uploads, etc.
3. **Custom URL structure** - Complex nested URLs or legacy URL patterns
4. **Function-based views** - Routers only work with ViewSets
5. **Fine control needed** - When you need precise control over each URL

**Example of when to skip routers:**

```python
# Bad: Using ViewSet for simple authentication
class AuthViewSet(viewsets.ViewSet):
    @action(detail=False, methods=['post'])
    def login(self, request):
        pass

    @action(detail=False, methods=['post'])
    def logout(self, request):
        pass

# Better: Use simple function-based views
from rest_framework.decorators import api_view

@api_view(['POST'])
def login(request):
    pass

@api_view(['POST'])
def logout(request):
    pass

# urls.py
urlpatterns = [
    path('auth/login/', login),
    path('auth/logout/', logout),
]
```

## Quick Reference Card

```python
# Basic router setup
from rest_framework.routers import DefaultRouter, SimpleRouter
from django.urls import path, include

router = DefaultRouter()
router.register(r'prefix', ViewSetClass, basename='name')

urlpatterns = [
    path('api/', include(router.urls)),
]

# Custom actions
@action(detail=True, methods=['post', 'get'])      # /prefix/{pk}/action/
def action_name(self, request, pk=None):
    pass

@action(detail=False, methods=['get'])             # /prefix/action/
def list_action(self, request):
    pass

@action(detail=True, url_path='custom-path')       # /prefix/{pk}/custom-path/
def custom_url(self, request, pk=None):
    pass

@action(detail=True, url_name='custom-name')       # URL name: basename-custom-name
def custom_name_action(self, request, pk=None):
    pass

# Router configuration
router = DefaultRouter(trailing_slash=False)       # No trailing slashes
router = SimpleRouter(use_regex_path=False)        # Use path() instead of re_path()

# Multiple routers
router_v1 = DefaultRouter()
router_v2 = DefaultRouter()
router_v1.register(r'authors', AuthorV1ViewSet)
router_v2.register(r'authors', AuthorV2ViewSet)

urlpatterns = [
    path('v1/', include(router_v1.urls)),
    path('v2/', include(router_v2.urls)),
]

# URL reversal
from django.urls import reverse
reverse('author-list')                             # /authors/
reverse('author-detail', kwargs={'pk': 1})         # /authors/1/
reverse('author-activate', kwargs={'pk': 1})       # /authors/1/activate/
```
